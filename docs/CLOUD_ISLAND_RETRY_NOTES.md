# 台北島預覽版：進度圖示與照片斷線恢復（開發中）

本次僅修改 `feature/firebase-sync`，原 GitHub Pages 正式網站不變。

## 進度圖示
- 每次 Firestore 收到五關文件更新，同步更新護照、關卡數量及島上 pin 的「✓／?」。
- 第一關 `demo2026/group01/missions/1` 的手動測試完成資料仍可能使第一關顯示完成。此修正不清除資料。

## 斷線恢復（開發模組）
- `photo-upload.js` 將壓縮後 JPEG 計算 SHA-256，將 sha256 存到 Cloud Storage 自訂中繼資料。
- 當同一名組員、同一關、同一欄位的既有檔案存在且 sha256、MIME、大小都一致，允許重用其路徑，避免 create-only 規則讓斷線重試永久卡住。
- 既有欄位若是不同照片、格式或容量，拒絕覆蓋並提示老師處理補拍。
- 對於目前已在 Storage 的舊測試照片（例如 S02 的 `lang1_photo.jpg`），因未寫入 sha256，自動恢復無法直接判定同一檔案，預期會拒絕。不能因此放寬規則。
- 儲存摘要只能證明同一個位元組內容；雲端後端仍必須獨立確認上傳者、小組、檔案存在、格式及唯一提交。
