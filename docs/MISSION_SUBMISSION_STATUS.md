# 共同成果提交 — 第一版開發狀態

2026-11-03：S01 / S02 已在 Firebase 預覽頁驗證同組即時監聽。先前由管理者手動新增 `activities/demo2026/groups/group01/missions/1` 的 `status=completed` 只是**同步測試紀錄**，不是正式學生作業；正式提交測試前應先移除這個測試文件，並留意兩個畫面恢復未完成。

## 已加入
- `mission-schema.js`：五關所需文字與照片欄位的瀏覽器端檢核；僅為便利的前端檢核。
- `mission-submission.js`：同組最多一筆關卡成果的交易式提交初版；會記錄組員代碼、Auth UID、伺服器時間及成果欄位。
- `tests/mission-schema.test.mjs`：五關有效及常見不完整答案的單元測試，執行 `npm run test:missions`。

## 尚未完成（因此不可部署提交功能）
1. 選擇照片的雲端檔案儲存方案。現有 Cloud Storage 需要 Blaze 方案；本專案仍在 Spark。
2. 真正上傳照片、限制檔案大小與類型、適當壓縮及照片讀取授權。
3. `mission-schema.js` 的 photoPaths 目前僅檢查格式，**無法驗證檔案真的存在**、是否屬於同組或是否由提交者上傳。不能以此代替伺服器端驗證。
4. Firestore 安全規則目前禁止任務成果的用戶端寫入；下一步需設計規則或可信任後端，並在 Emulator 補測無附件、假附件路徑、他組路徑、重複提交、非組員提交與時間／提交者偽造。
5. 將提交功能整合進既有 `index.html` / `script.js`；當伺服器成功寫入才顯示過關。
6. 教師後台只包含四個定稿功能，不增加其他監控項目。
7. 考量學生的真實身份驗證與裝置遺失後的重新加入。

**不要把雲端路徑存在就當成已上傳照片的證明；也不要直接更動正式的 `firestore.rules`。**
